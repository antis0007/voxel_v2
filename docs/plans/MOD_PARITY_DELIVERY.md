# Mod inspiration delivery backlog

The [canonical feature matrix](../research/MOD_FEATURE_MATRIX.md) is the full feature backlog for [Addendum A](../specs/MOD_ADDENDUM.md). Its 422 stable IDs cover 153 inherited entries, 131 detailed A.1–A.13 entries, 80 entries for the eight major A.14 systems, 48 other A.14 entries, and 10 shared A.15 requirements. Keep every ID in the delivery ledger, including work blocked by a prerequisite or awaiting a design decision. Use the [research index](../research/README.md#mod-families) for attribution and version evidence, and the [master plan](../MASTER_PLAN.md#5-feature-adoption-routing) for subsystem owners and milestones. Exact inherited balance values require their own design decision before adoption.

## Slice order and evidence

1. **Close ordinary play loops.** Recheck tools, smeltery, agriculture, recipes, building variants, storage, navigation and starter magic against current loaders and gameplay entry points. Follow discovery, crafting, use, feedback and save/reload. The [November 3 parity audit](2026-11-03-playability-parity-gaps.md) and [tech parity plan](2026-10-25-tech-mod-parity.md) are evidence leads. Recheck their dated gaps before scheduling.
2. **Connect production and controls.** Prioritize shared typed ports, inventory reservations, power, logic and machine diagnostics before expanding machine catalogs. Bring up one complete processing chain with an ordinary acquisition route and a visible reason for every stall.
3. **Add moving work and field interactions.** Connect bodies, rails, build plans, fluids, pressure, pollutants, heat, ecology and security through bounded authoritative services. Use the [causal-world plan](2026-11-05-axiom-causal-world.md) to choose a province where failures and recovery are observable.
4. **Expand persistent civilization and exploration.** Build local trade, hauling, work and construction on actual settlements and supplies. Add deeper exploration, habitats and remote operations as their ownership and persistence contracts become available. Follow the [civilization direction](../superpowers/specs/2026-11-06-axiom-direction-persistent-civilization-simulation.md) for simulation fidelity and budget boundaries.
5. **Open high-consequence routes.** Stage orbit, remote logistics, dimensions, reactor/accelerator systems and exotic magic separately. Each route requires ordinary entry, controlled operation, an interruption path, durable ownership and a bounded resource or failure budget.

For every matrix ID, record its owner, intended player action and result, dependencies, code/data entry points, unlock and resource costs, art/audio/UI/text work, save and network impact, relevant hardware budget, and acceptance checks. The authoring tool should start with the owning SDD and link the immutable source row. Record evidence separately as **planned**, **source-backed**, **build-checked**, **scenario-verified**, or **accepted**, with the exact revision, config, fixture and outcome. Mark blocked rows with the missing contract or decision. A prototype, capture or compile can advance only the evidence dimension it actually demonstrates.

Add new inspiration as a stable row or an explicit link to an existing row. Carry forward Axiom’s original progression, lore and authored art direction. Route conflicting mechanics through a documented design decision. Keep source identities and old rows searchable when a shared implementation supersedes their original mapping. The [Dev Toolkit spec](AXIOM_DEV_TOOLKIT.md) defines how to turn those rows into bounded work packets.
